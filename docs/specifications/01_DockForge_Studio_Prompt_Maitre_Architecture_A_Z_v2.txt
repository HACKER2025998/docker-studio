1. Pourquoi une Application Desktop Native (.exe, .deb, .bin) et Non une App Web ?
L'Agent Codeur doit comprendre pourquoi DockForge Studio est obligatoirement compilé en binaire natif Desktop (Tauri v2 + Rust) et ne peut pas être un simple site web :
Accès Direct au Noyau et au Démon Docker : Un navigateur web est enfermé dans une sandbox (CORS, impossibilité de lire `/var/run/docker.sock` ou `//./pipe/docker_engine`, impossibilité de vérifier si `systemd`, `WSL2` ou `containerd` sont installés).
Élévation de Privilèges Native (Polkit / UAC) : Pour démarrer un service Docker éteint (`systemctl start docker`), ajouter l'utilisateur au groupe `docker`, ou allouer une adresse IP sur un pont réseau (`macvlan`/`bridge`), l'application doit invoquer `pkexec` (Linux Polkit) ou l'invite Administrateur UAC (Windows).
Vérification des Ports Locaux avant Création : Avant de lancer un conteneur PostgreSQL sur `5432` ou MySQL sur `3306`, le binaire Rust effectue un `TcpListener::bind` local pour vérifier en 0.2ms si le port est libre ou déjà occupé par un processus hôte.

3.2. Parcours Détaillé : Exemple de Création d'un Conteneur PostgreSQL ou MySQL
Lorsque l'utilisateur clique sur la carte **[PostgreSQL]** (ou n'importe quel autre service), un tiroir modal lumineux en 3 étapes rapides s'ouvre :
Étape 1 — Identité & Identifiants : L'utilisateur saisit le Nom du conteneur (ex: `pg-campus-db`), choisit la version (`postgres:16-alpine`), saisit le **Nom d'utilisateur** (`bernard_admin`), le **Mot de passe** (champ avec icône œil + bouton `[🎲 Générer 24 caractères]`), et le **Nom de la base par défaut** (`campus_prod`).
Étape 2 — Configuration Réseau (Local vs IP Spécifique) : L'utilisateur choisit comment exposer son conteneur grâce à 3 boutons radio visuels :  • Option A [🔒 Local Uniquement (127.0.0.1)] : Le conteneur n'est accessible que depuis ce PC (`127.0.0.1:5432:5432`).  • Option B [📡 Réseau Local / IP Spécifique (LAN)] : L'application liste les adresses IP de la machine (ex: `192.168.1.45` ou `0.0.0.0`) ou permet d'attribuer une **IP dédiée statique** sur un sous-réseau Docker (`172.28.0.10`).  • Vérificateur de Port en Temps Réel : Si le port `5432` est déjà utilisé sur le PC, un badge ambre s'affiche immédiatement (« ⚠️ Port 5432 occupé par un autre service ») et propose en 1 clic le prochain port libre (`5433`).
Étape 3 — Stockage & Persistance : Bouton radio `[💾 Volume Docker Géré (Recommandé)]` ou `[📂 Dossier Local sur mon PC]` pour ne jamais perdre les données si le conteneur est redémarré.
3.3. Exécution, Rapport des Logs en Temps Réel & Diagnostic d'Erreurs Clair
Dès que l'utilisateur clique sur **[🚀 Créer & Lancer le Conteneur]**, l'écran passe sur le **Console & Diagnostic Reporter** :
1. Téléchargement & Création : Jauge de progression couche par couche (Layer Pull Progress) via le flux streamé de l'API Docker, suivie du démarrage du conteneur et de la vérification que la base de données accepte réellement les connexions (`pg_isready` ou `mysqladmin ping`).
2. Si Tout S'est Bien Passé (Rapport de Succès) : Bannière Émeraude `#059669` : « ✅ Conteneur `pg-campus-db` créé, démarré et prêt à recevoir des connexions en 3.4 secondes ! » + affichage du résumé des logs d'initialisation.
3. Si une Erreur Survient (Traducteur d'Erreurs Intelligent) : Si le conteneur échoue ou s'arrête (`Exit Code != 0`), le moteur Rust `ContainerLogDoctor` analyse les 50 dernières lignes de `stderr` et affiche une explication humaine en français avec un bouton de réparation automatique :

4. Module 3 : Export JSON des Identifiants & Coffre-Fort Persistant (Credentials Vault)
C'est l'une des fonctionnalités phares demandées : dès que le conteneur est créé avec succès, l'utilisateur reçoit toutes les informations de connexion dans une carte récapitulative propre, peut les télécharger en `.json`, et peut revenir les consulter à tout moment tant que le conteneur n'a pas été supprimé.
4.1. Structure Exacte du Fichier JSON Téléchargeable (`<nom_conteneur>_credentials.json`)
Sur l'écran de succès (et à tout moment dans la fiche du conteneur), l'utilisateur dispose de 3 boutons d'export : **[📥 Télécharger les Identifiants (.json)]**, **[📋 Copier l'URI de Connexion]**, et **[📄 Copier en format .env]**. Le fichier JSON généré suit ce standard universel :

4.2. Cycle de Vie et Consultation Permanente dans l'Application
Stockage Chiffré Local (AES-256-GCM) : Dès la création du conteneur, cette fiche JSON est enregistrée dans la table SQLite locale `managed_containers_vault`.
Consultation à Volonté : Si l'utilisateur ferme l'application, éteint son PC et revient 2 semaines plus tard, il clique sur son conteneur dans la section **« 📦 Mes Conteneurs & Accès »** : il retrouve immédiatement le mot de passe (masqué par défaut avec bouton `[👁️ Afficher]`), l'IP, le port, les logs, et le bouton **[📥 Re-télécharger le JSON]**.
Synchronisation avec la Suppression : Tant que le conteneur existe (même s'il est arrêté `Stopped/Exited`), ses identifiants restent accessibles. Si l'utilisateur supprime définitivement le conteneur, l'application lui demande : « Voulez-vous également supprimer la fiche d'identifiants ou l'archiver dans l'historique ? ».
5. Module 4 : « Image Forge » — Créateur d'Images sur Mesure & Lancement Direct
L'utilisateur veut pouvoir créer ses propres images personnalisées ultra-rapidement sans écrire manuellement un `Dockerfile` complexe, puis créer des conteneurs basés sur ces images en 1 clic.
5.1. Le Constructeur Visuel d'Images (Visual Image Studio)
Dans l'onglet **« 🏗️ Créer une Image (Image Forge) »**, l'utilisateur construit une image en 4 clics :
1. Choix de la Base ou de la Stack : Sélectionne un OS ou un environnement de base : `Ubuntu 24.04`, `Debian 12 Slim`, `Alpine 3.20`, `Arch Linux`, `Python 3.12`, `Node.js 22`, `PHP 8.3 + Apache/Nginx`, `Rust`, `.NET 8 SDK`, `Java 21 OpenJDK`.
2. Cases à Cocher des Outils & Extensions : Une grille visuelle permet de cocher les paquets à pré-installer dans l'image (ex: `curl`, `git`, `vim`, `nmap`, `iproute2`, `ffmpeg`, `pdo_pgsql`, `pdo_mysql`, `redis`, `supervisor`).
3. Dossier Projet & Port par Défaut : Optionnellement, l'utilisateur sélectionne un dossier de son PC à intégrer dans `/app`, indique la commande de démarrage (ex: `npm run start` ou `python main.py`) et le port exposé.
4. Nom & Tag de l'Image : Ex: `mon-api-laravel:v1.0` ou `kali-audit-custom:latest`.
5. Compilation Temps Réel & Passage Direct au Conteneur : En cliquant sur **[🔨 Construire l'Image]**, le backend Rust génère le `Dockerfile` optimisé (multi-stage, cache APT/Pacman nettoyé), lance le build via BuildKit, affiche les logs étape par étape, et dès que l'image est prête, affiche un gros bouton Émeraude : **[🚀 Créer un Conteneur basé sur cette Image maintenant]** qui pré-remplit automatiquement le formulaire du Module 2 !
